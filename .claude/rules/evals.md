# evals 的规则（D10、D22）

- 跑真实模型要花钱。跑之前先打印预计花费，用 `--max-usd` 设上限，等用户做完花费确认（D26）再跑。
- 改了评分器或评审，先跑两条免费的基线：oracle 必须全部通过，null 必须全部不通过。
- 基础设施错误写进 `errors.jsonl`，不计分。不要把网络问题算成 agent 的失败。
- 比较两次结果时，看 95% 置信区间。差距小于噪声底线，就不下结论。
- 报告里的每个数字，都要能从 `results.jsonl` 重新算出来。
- 评审和被测不要用同一个模型。评审先和人工标注校准，一致率达到 90% 以上，才能用它来指导改动。
- 用例和评分标准进 git。试验的产物放在 `$LOOPBACK_HOME/evals/` 下，不进 git。
